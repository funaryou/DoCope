# DoCope — プロジェクトの思想と設計方針

## 1. このアプリを作る理由

開発や学習を続けていると、プロジェクトごとのソースコードだけでなく、設計書、調査メモ、AIとの対話記録、検証結果なども増えていきます。

しかし、それらの資料は一つのサービスや一つの形式にまとまっているとは限りません。プロジェクトごとのフォルダに保存されるため、「どこに何があるか」を思い出すこと自体が負担になります。

DoCope は、複数のプロジェクトとその中にあるドキュメントを、プロジェクト単位で見渡せるようにするためのアプリです。

## 2. 解決したい課題

DoCope が特に解決したいのは、次のような状況です。

- プロジェクトの保存場所が増え、必要なフォルダを探すのに時間がかかる
- ドキュメントの内容を確認するために、毎回ファイル管理アプリやエディタを開く必要がある
- プロジェクトごとの目的や説明を、フォルダ名だけでは把握しにくい
- AIとの会話ログや設計資料など、コード以外の成果物も含めて整理したい
- 開発の途中で作った資料が、後から見つけにくくなる

そこで、プロジェクトの登録情報とファイルの閲覧場所を一つにまとめ、必要な情報へ移動するまでの距離を短くします。

## 3. DoCopeの基本的な考え方

### プロジェクトを起点にする

ファイル単体ではなく、プロジェクトを中心に情報を整理します。プロジェクト名、保存場所、説明、識別色、アイコンを登録することで、フォルダを開く前にそのプロジェクトが何なのかを把握できるようにします。

### ローカルの資料をそのまま扱う

DoCope は、資料を独自の場所へ移動したり、別のサービスへアップロードしたりするのではなく、利用者が指定したローカルフォルダを参照します。既存のファイル構成や開発環境を変えずに使えることを重視しています。

### 閲覧までの操作を減らす

プロジェクトを選び、フォルダツリーからファイルを選ぶだけで内容を確認できることを目指します。資料を読むための準備操作を減らし、調査や振り返りに集中できる状態を作ります。

### 情報量と見通しを両立する

プロジェクト一覧では、名前・パス・説明・更新日・接続状態を確認できます。ファイル閲覧画面では、左側のツリーと右側のビューアを分け、現在地を見失わずに内容を読める構成にしています。

## 4. 現在の実装範囲

提出時点では、DoCope の中心となる次の流れを実装しています。

1. ローカルのプロジェクトフォルダを登録する
2. 登録したプロジェクトを一覧から選択する
3. フォルダツリーを確認する
4. ファイルを選択して内容を閲覧する
5. 必要に応じてプロジェクト情報を編集・削除する

また、存在しないフォルダを登録しないための確認や、表示対象を調整する設定を用意しています。ローカルファイルを扱うアプリだからこそ、意図しない場所を参照しないことや、パスの妥当性を確認することも重視しています。

## 5. デザインの方向性

画面は、資料を探すための「索引」と、内容を読むための「作業場」を組み合わせたものとして設計しています。

- プロジェクト一覧は、登録済みの対象を見渡せる索引
- サイドバーは、プロジェクト内の構造を確認するためのナビゲーション
- メイン領域は、選択したファイルを読むためのビューア
- プロジェクトごとの色やアイコンは、識別のために使い、装飾を目的にしない
- 情報量の多い画面でも、パスや状態が読み取りやすいことを優先する

見た目の詳細なルールは、[DESIGN.md](../DESIGN.md) にまとめています。

## 6. 今後の展望

今後は、現在の「登録して探して読む」という中心体験を保ちながら、次の方向へ発展させたいと考えています。

- プロジェクトやファイルをより早く見つけるための検索
- よく見るファイルやプロジェクトへのアクセス性向上
- ドキュメントの種類に応じた表示方法の拡充
- 閲覧履歴や最近更新された資料の把握
- プロジェクトの状態や関連資料をより分かりやすくする整理機能
- 画面サイズや利用環境に応じた操作性の改善

これらはすべて同時に実装するのではなく、利用時に発生する不便さを確認しながら、具体的なIssueへ分解して進めます。
